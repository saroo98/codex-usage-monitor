Release integrity

Code signing policy

Roles

  • Author/committer: @saroo98
  • Reviewer: @saroo98
  • Release approver: @saroo98

Trusted source

Only source committed to the public canonical repository may be used for official signed artifacts. Private planning files, local patches, unpublished source, and manually substituted binaries are excluded.

Build requirements

Official release artifacts must be generated from a tagged commit by the repository's public GitHub Actions workflow on a clean runner. The workflow must build and test from declared source and dependencies, create checksums and provenance, and submit the generated artifacts for signing without manual replacement.

Approval

The approver checks the tag, commit, test results, dependencies, artifact names, versions, architectures, hashes, licenses, security results, and absence of secrets or private material before approving signing.

Signing service

The project intends to use SignPath Foundation for eligible open-source release signing. Until that service is enabled, unsigned releases must be explicitly identified as unsigned. Development certificates are never represented as public production trust.

Verification

Download only from the official GitHub Releases page. Compare the file's SHA-256 hash with the published checksum and, for signed releases, verify the Authenticode signer.

The complete policy is available in CODE_SIGNING_POLICY.md.
